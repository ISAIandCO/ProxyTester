# Проверка версии 1.1.1 — загрузка Chromium через VPN

Дата: 15 ноября 2026 года. Проверенный код:
[`e94cb67`](https://github.com/ISAIandCO/ProxyTester/commit/e94cb67108ab9793a45677aa98c46af3660ed6d4).

* [Windows workflow](https://github.com/ISAIandCO/ProxyTester/actions/runs/43749965015)
* [Windows x64 portable с GUI](https://github.com/ISAIandCO/ProxyTester/actions/runs/43749965015/artifacts/14176215795)

## Причина и исправление

На Windows runner воспроизведено зависание Chromium на `about:blank` при
переходе к Google через настоящий локальный VLESS-сервер и аутентифицированную
цепочку прокси приложения. HTTP-клиент через тот же маршрут получал HTTP 200,
TCP и TLS устанавливались, проверка внешнего IP самого Chromium проходила.
Отключение правил DNS и остальных дополнительных аргументов браузера не помогло.

При отключении HTTP/2 NotebookLM загрузился в headed и headless Chromium.
Для входа и браузерных проверок добавлен общий `--disable-http2`; используется
HTTPS с HTTP/1.1, проверка сертификатов сохраняется. Это проверенный обход
зависания на воспроизведённой цепочке, а не утверждение о неисправности HTTP/2
на всех VPN или о точной причине внутри Chromium/прокси.

Перед входом Chromium проверяет свой внешний IP и состояние WARP по тому же
маршруту, который затем используется для сервиса. При несовпадении вход не
продолжается. В GUI видны этапы подключения и безопасная причина ошибки.

Ошибки CSS/regex отделены от сетевых, в отчёт добавлены этап и причина.
Проверка с некорректным CSS возвращает `check_error`, а не `network_error`.
Стандартные селекторы NotebookLM/Gemini проверены на синтаксическую корректность.

## Результат

**76 тестов прошли без пропусков:** 42 модульных, 23 интеграционных,
1 браузерный для HTML-отчёта и 10 GUI-проверок. Windows Server 2025 x64,
Python 3.12.10, Xray 26.11.9, sing-box 1.14.4, Playwright 1.62.0.
Время набора — 96 секунд. Готовые EXE прошли smoke-проверки.

Добавлены реальные проверки HTTPS через аутентифицированную цепочку
sing-box → Xray → VLESS: headed/headless Chromium и полный путь команды входа
с сохранением сессии. Локальный TLS использует отдельный временный сертификат;
разрешение этого конкретного сертификата действует только в тесте.

Публичная проверка использует обычные настройки приложения и стандартные
селекторы: NotebookLM и Gemini открываются через VLESS в headless Chromium;
затем настоящий headed-вход открывает NotebookLM и сохраняет пустую сессию
без ввода аккаунта. Проверяется загрузка и совпадение внешнего IP, а не
доступность функций аккаунта. Неавторизованная страница может оставаться
«Не подтверждено». Публичный smoke-тест включается через `PROXYTESTER_LIVE_SMOKE=1`.

Сохранены проверки VLESS TCP, XHTTP, REALITY, XHTTP+REALITY,
Hysteria2+Salamander+TLS и WireGuard поверх VLESS/XHTTP/Hysteria2,
download/upload, отсутствия прямого fallback после остановки VPN,
регистрации через VPN, генерации ключа WireGuard, HWID header/query/bearer,
429, кэша, параллельной изоляции, отмены/возобновления, HTML-отчёта и GUI.

Сборка содержит `ProxyTester.exe` и `ProxyTesterCLI.exe` с общей папкой runtime,
ядрами и Chromium. Существующий config.json читается без конвертации.
Проверяются версия готового CLI и создание/закрытие окна готового GUI.

## Границы проверки

* Локальный регистрационный API — фикстура ответов Cloudflare. Шифрование,
  ключи, VPN-транспорт и передача данных настоящие. Это не публичный WARP.
* Действующая коммерческая подписка/HWID и Google-аккаунт не предоставлены.
  Принятие HWID поставщиком, публичная регистрация WARP через его серверы
  и NotebookLM/Gemini с аккаунтом пользователя остаются непроверенными.
* Положительный статус сервиса означает прохождение заданной проверки
  готовности интерфейса. Создание блокнотов, отправка запросов и платные
  операции автоматически не выполняются.
* Локальные скорости проверяют измеритель, а не качество коммерческих VPN.
* CI выполнялся на Windows Server 2025. Отдельного запуска на физических
  Windows 10/11 в этой работе не было.
* Проверено штатное прерывание. Принудительное завершение через Task Manager
  или отключение питания не проверялись.

В исходной Linux-среде прошли 42 модульных теста.
Нативные Tk-тесты выполнялись на Windows, поскольку в Linux-среде нет display.
