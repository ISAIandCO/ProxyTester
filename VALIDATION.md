# Проверка версии 1.2.0 — выбор браузера

Дата: 16 ноября 2026 года.

В этой версии добавлены поиск Chrome/Edge/Brave через реестр Windows,
стандартные папки и PATH, список найденных установок и сохранение выбора.
Проверяются отмена выбора, передача выбранного пути в команду входа,
пользовательские пути и отсутствие дубликатов. В Windows дополнительно
запускаются найденные Chrome и Edge через аутентифицированный VPN-маршрут.

Набор содержит 82 проверки: 46 модульных, 24 интеграционные, 11 GUI и
1 браузерную для отчёта. Локально прошли 46 модульных проверок и 3 проверки
worker; 8 нативных Tk-проверок требуют Windows или display.

Перед публикацией релиза workflow обязан успешно выполнить Windows-набор,
собрать portable ZIP и проверить готовые CLI/GUI. Результат и журнал:
[Test and build Windows portable](https://github.com/ISAIandCO/ProxyTester/actions/workflows/windows.yml).

Релиз публикуется только после успешной сборки, вручную с флагом
`publish_release` или по точному заголовку коммита `Release vВЕРСИЯ`.
Тег и версия берутся из `proxytester/__init__.py`; существующий публичный
релиз не перезаписывается.

Google-аккаунт и действующая коммерческая подписка пользователя в CI не
используются. Успешный вход в конкретный аккаунт и работа конкретной
подписки требуют проверки на стороне пользователя.

# Проверка версии 1.1.2 — ручной вход через Brave

Дата: 16 ноября 2026 года. Проверенный код:
[`f3d0c83`](https://github.com/ISAIandCO/ProxyTester/commit/f3d0c838cedb6c0dc6334de1fdb64f1ed8270093).

* [Windows workflow](https://github.com/ISAIandCO/ProxyTester/actions/runs/43752125539)
* [Windows x64 portable с GUI](https://github.com/ISAIandCO/ProxyTester/actions/runs/43752125539/artifacts/14176464342)

## Изменение входа

Прежний вход открывал Chromium через `playwright.chromium.launch`, то есть
со стандартными флагами автоматизации, включая `--enable-automation`.
Google показывает сообщение «Возможно, этот браузер или приложение небезопасны».
[Google допускает отказ для автоматизированных браузеров](https://support.google.com/accounts/answer/7675428?hl=en).
Скриншот сам по себе не определяет все причины отказа конкретному аккаунту.

Теперь браузер запускается отдельным процессом: автоматически выбирается
Brave → Chrome → Edge, затем встроенный Chromium. Явный путь в параметрах
имеет приоритет. Указывайте путь к Chromium-совместимому браузеру; Firefox
этим способом не поддерживается.

Для подключения используется локальный CDP и новый временный профиль.
Приложение не добавляет `--enable-automation`, не изменяет свойства браузера
скриптами, не читает обычный профиль и не вводит пароль или коды подтверждения.
Контекст входа по-прежнему использует аутентифицированный прокси выбранного VPN;
перед сервисом проверяется совпадение внешнего IP и состояния WARP.

После ручного входа кнопка «Сохранить сессию» экспортирует cookies, localStorage
и IndexedDB в прежний JSON-формат. Браузер закрывается, временный профиль удаляется.
Сохранённая сессия используется в изолированных контекстах проверок VPN/WARP.

Сохранено исправление 1.1.1: отключение HTTP/2 для зависавшей цепочки прокси,
HTTPS и проверка сертификатов включены. Ошибки CSS/regex отделены от сетевых.

## Результат

**78 проверок прошли без пропусков:** 44 модульных, 23 интеграционных,
1 браузерная для HTML-отчёта и 10 GUI-проверок. Windows Server 2025 x64,
Python 3.12, Playwright 1.62.0, Brave 1.99.57, Xray 26.11.9, sing-box 1.14.4.

В CI скачан официальный Brave 1.99.57 Windows x64; перед запуском проверен
SHA-256 архива. Brave применяется только для проверки входа и не включается
в portable-сборку. Проверены HTTPS через аутентифицированный VLESS, внешний IP,
`navigator.webdriver == false` у отдельно запущенного браузера, сохранение
контрольных cookies/localStorage и их чтение в новом headless Chromium.
Последняя проверка использует тестовую сессию локального HTTPS-сайта.

Публичный smoke-тест проверяет загрузку NotebookLM/Gemini и открытие NotebookLM
новым способом в Brave. Google-аккаунт в CI не вводится: успешный вход в аккаунт
пользователя не подтверждён. Это необходимо проверить вручную на его стороне.

Сохранены тесты VLESS TCP/XHTTP/REALITY/XHTTP+REALITY,
Hysteria2+Salamander+TLS, WireGuard поверх VLESS/XHTTP/Hysteria2,
download/upload, отсутствия прямого fallback после остановки VPN,
регистрации через VPN, генерации ключа WireGuard, HWID header/query/bearer,
429, кэша, параллельной изоляции, отмены/возобновления, HTML-отчёта и GUI.

Сборка содержит `ProxyTester.exe` и `ProxyTesterCLI.exe` с общей папкой runtime,
ядрами и Chromium. Существующий config.json читается без конвертации.
Проверяются версия готового CLI и создание/закрытие окна готового GUI.

Готовые CLI и GUI прошли smoke-проверки. Время набора тестов — 92 секунды.

## Границы проверки

* Локальный регистрационный API — фикстура ответов Cloudflare. Шифрование,
  ключи, VPN-транспорт и передача данных настоящие. Это не публичный WARP.
* Действующая коммерческая подписка/HWID и Google-аккаунт не предоставлены.
  Принятие HWID поставщиком, публичная регистрация WARP через его серверы
  и NotebookLM/Gemini с аккаунтом пользователя остаются непроверенными.
* Положительный статус сервиса означает прохождение заданной проверки
  готовности интерфейса. Создание блокнотов, отправка запросов и платные
  операции автоматически не выполняются.
* Локальные скорости проверяют измеритель, а не качество коммерческих VPN.
* CI выполнялся на Windows Server 2025. Отдельного запуска на физических
  Windows 10/11 в этой работе не было.
* Проверено штатное прерывание. Принудительное завершение через Task Manager
  или отключение питания не проверялись.

В исходной Linux-среде прошли 44 модульных теста.
Нативные Tk-тесты выполнялись на Windows, поскольку в Linux-среде нет display.
